# 조용한 관종의 일본 · 일본 행사 캘린더

빌드 없이 HTML/CSS/JS만으로 만든 정적 사이트예요. 일정은 전부 `events.json`에 있어요.

## 파일
- `index.html` 화면 / `style.css` 디자인 / `app.js` 필터·상태 계산
- `events.json` 일정 데이터 (이것만 고치면 돼요)

## 일정 수정하기 (events.json)
- `base_date`: 상단 "기준일" (예: `"2026-10-20"`)
- `last_updated`: 상단 "마지막 업데이트" 날짜 (`YYYY-MM-DD`). **매주 월·목 업데이트할 때마다 반드시 그날로 고쳐요.** "다음 업데이트"는 이 날짜 다음의 월요일·목요일로 사이트에서 자동 계산돼요.
- `is_sample`: `true`면 "예시 데이터" 배너 표시 → 실제 데이터로 바꾸면 `false`로
- `events` 항목 필드:
  | 필드 | 설명 |
  |---|---|
  | title_ko / title_ja | 한국어 / 일본어 제목 |
  | category | 팝업스토어, 콜라보카페, 전시·행사, 축제, 가챠, 쿠지, 플리마켓 중 하나 (카테고리마다 배지 색이 달라요) |
  | area | 도쿄, 오사카, 나고야, 전국 ... (지역 목록은 자동 생성) |
  | venue | 장소 (가챠·쿠지는 "전국 판매처" 등) |
  | start / end | `YYYY-MM-DD` (모르면 `null`, 가챠·쿠지 start=입고/발매일) |
  | reservation | 필요 / 불필요 / 선택 |
  | price | 가격 문구 |
  | official_url / source_url | 공식 링크 / 출처(X 게시물 등) |
  | notes | 메모 |
  | checked_date | 마지막으로 확인한 날 |
  | series | (선택) 묶음 키. 같은 행사가 날짜만 다를 때 같은 값을 넣으면 한 카드로 묶여요 (예: `"oi-flea-2026"`) |

상태는 오늘 날짜로 자동 계산돼요: 진행 중 / 예정 / 곧 종료(7일 이내) / 종료(자동 숨김).
가챠·쿠지는 입고 중 / 입고 예정 / 곧 종료(end가 있을 때만)로 표시되고, 상단 토글에서는 입고 중=진행 중, 입고 예정=예정으로 묶여요.
쉼표·따옴표 하나만 틀려도 사이트가 안 뜨니, 수정 후 https://jsonlint.com 에서 검사해 보세요.

## 자세히 보기 · 갤러리 (선택)
- 카드의 제목·썸네일·**자세히 보기** 버튼을 누르면 카드형 소개 창이 떠요 (X·바깥 클릭·Esc로 닫기). events.json 정보로 자동 생성돼요.
- 메뉴·굿즈·상품 라인업 사진을 넣고 싶으면 행사에 아래 필드를 추가하세요. 없으면 소개 카드만 나와요.
```json
"gallery": [
  {"group": "카페 메뉴", "img": "공식 이미지 주소", "caption_ko": "한국어 이름", "caption_ja": "원문 이름", "price": "1,190엔 (세금 포함)", "source": "해당 공식 페이지"}
],
"gallery_source": "https://공식사이트",
"gallery_note": "이미지는 공식 사이트 이미지(실제와 다를 수 있음)"
```
- `group`이 같은 것끼리 묶여서 제목과 함께 보여요 (예: 카페 메뉴 / 오리지널 굿즈 / 상품 라인업).
- 이름·가격은 공식 페이지 표기 그대로만, 이미지는 공식 주소를 그대로 링크해요 (재업로드 X). 확인 못 한 항목은 넣지 않아요.

## GitHub Pages로 무료 배포
1. GitHub에서 새 공개 저장소 만들기 (예: `japan-events`)
2. 이 폴더 파일들 업로드 (`preview/` 폴더는 빼도 돼요)
3. 저장소 Settings → Pages → Branch `main` / `/ (root)` → Save
4. 1~2분 뒤 `https://아이디.github.io/japan-events/` 로 접속
5. 업데이트할 때는 GitHub에서 `events.json`을 열어 연필(✏️) 버튼으로 고치고 Commit 하면 끝

## 검증 파이프라인 (tools/)
- 한 번에 실행: `tools/run.sh` → 근거 채우기 + 재검증 + 종료 행사 삭제 + `review.md` 생성
- 공식 페이지 원문에 '시작일〜종료일'이 그대로 있는 항목만 `events.json`(라이브)에 남고, 나머지는 `pending.json`(사유 포함)으로 빠짐
- 후보 수집: `/workspace/.pwvenv/bin/python tools/collect.py URL ...` → `candidates.json`

## 검색·여행 기간·임박 표시 (2026-10-16)
- **검색창**: 작품명(한/일)·장소·요약을 실시간 검색. 카테고리·지역·상태 필터와 함께 동작
- **✈️ 여행 기간**: 시작~종료일을 넣으면 그 기간에 하루라도 열리는 행사만 표시 (종료일 없는 행사·발매일만 있는 쿠지/가챠는 시작일부터 계속 진행으로 간주). 초기화 버튼 있음
- **임박 표시**: 종료 14일 이내 🔥 D-n 주황 테두리, 7일 이내 빨간 테두리, 당일은 '오늘 종료'. 7일 이내 발매 예정 쿠지·가챠는 🆕 곧 발매

## 잡지 부록 추가하는 법

1. 출판사 공식 페이지(예: 宝島社 `tkj.jp/<잡지>/next`, 소학관 ちゃおプラス, 講談社 なかよし 공식)에서 **잡지명·호수·발매일·부록 내용**이 함께 적힌 문장을 찾아요.
2. `events.json`에 `category: "잡지 부록"`, `area: "전국"`, `venue: "서점·편의점"`, `start: 발매일`, `end: null`, `price: "1,980엔(세금 포함)"`처럼 넣고, `evidence`에 `{url, tier:"official", quote}`(페이지 원문 그대로)를 넣어요. 썸네일은 그 부록의 공식 이미지만 쓰고 `thumbnail_source`에 출처를 적어요. 없으면 비워 두면 글자 썸네일이 나와요.
3. `python tools/verify.py`를 실행하면 인용문과 발매일을 다시 대조해요. 확인 안 되면 `pending.json`으로 빠져요.
4. 사이트에서는 발매일 전 `발매 예정`, 발매 후 `발매 중`으로 보이고, **발매 35일이 지나면 자동으로 사라져요**(다음 호로 교체). 지도·날씨는 표시하지 않아요.

## 날짜만 다른 같은 행사 묶기 (2026-10-19)
- events.json은 **지금처럼 날짜별로 한 항목씩** 넣어요 (verify·정기 업데이트 그대로).
- 사이트가 화면에 그릴 때 자동으로 한 카드로 묶어요. 묶는 기준: `series` 값이 같거나, `series`가 없으면 **category + title_ko + official_url이 모두 같을 때**.
  - 그래서 새 날짜를 추가할 땐 제목·공식 URL을 기존 항목과 **글자 하나까지 똑같이** 써요. 제목을 다르게 쓰고 싶은데 묶여야 하면 모든 날짜에 같은 `series`를 넣어요.
  - 반대로 전기/후기처럼 따로 보여야 하는 건 제목을 다르게 (예: "(전기)", "(후기)").
- 묶음 카드: 다음 개최일 + D-day, 남은 날짜 목록(6개 넘으면 "+N개 더 보기"), 날짜별 시간이 다르면 시간별로 묶어 표시.
  - 시간은 각 항목 `notes` 맨 앞의 `8:45~14:15 (설명)` 형식에서 읽어요. 시간을 모르면 넣지 않아요("공식 안내 확인"으로 표시).
  - 날짜 나열 메모(예: "주말 위주 개최: 10/24·25…")는 날짜 목록으로 대체돼서 숨겨져요.
- 지난 날짜는 자동으로 빠지고, 마지막 날짜가 지나면 카드가 사라져요. 여행 기간 필터는 남은 날짜 중 하루라도 겹치면 표시하고 그 날짜를 강조해요.
